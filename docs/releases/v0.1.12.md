More of git's everyday commands in `scn`, history that agrees with git's, and a server that repacks its storage on its own.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

**Release packages.** As in v0.1.11, the server `scion` comes in `scion-server-v0.1.12-<target>.tar.gz` and the client in `scn-v0.1.12-<target>.tar.gz`, with `SHA256SUMS` and `install.sh`. The targets are:
- `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer);
- `aarch64-apple-darwin` and `x86_64-apple-darwin`.

**Docker image.** `opencsghq/scion:0.1.12` on Docker Hub, also as `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.12`, for `linux/amd64` and `linux/arm64`; both are also tagged `latest`.

## Changes

See [coming from git](https://github.com/OpenCSGs/scion/blob/main/docs/guide/coming-from-git.md) for each command.

**New commands and options**
- **`scn sync --abort`** gives up a sync that stopped on conflicts and puts back the files and pending commits from before it (`scn rebase --abort` too).
- **`scn commit -m MSG PATH...`** commits only the changes at or under those paths, relative to the current directory.
- **`scn clean`** removes untracked files, as `git clean` does: `-n` to list, `-f` to remove, `-d` for directories, `-x` for ignored files as well.
- **`scn stash`** puts local changes aside on the server and brings them back: `push`, `list`, `show`, `apply`, `pop`, `drop`, with a three-way merge when the working copy moved on.
- **`scn reflog [REF]`** shows how a branch or tag moved, from the server's log of it, so it covers everyone's lands: created, fast-forward or forced, when, and by whom (`fast-forward by alice`).
- **`scn switch --detach REV`** (and `scn checkout REV`) checks out any commit on no branch.
- **`scn grep`** searches like `git grep`: without a revision the working tree (HEAD on the server, files changed locally searched on your machine), with one that commit on the server, without a checkout.
- **Annotated tags:** `scn tag -a NAME -m MSG` keeps a message and a tagger, `scn tag -n` lists them, and `scn show NAME` shows them. The git gateway fetches and pushes them as tag objects with their SHAs, and `scn import git` keeps them.
- **`scn log --follow -- FILE`** follows a file across renames and copies, as git does.

**History as git shows it.** Checked against git on the full history of a 6,338-commit repository:
- `scn log PATH` leaves out a merge that took the path as it was on a merged branch, as git's history simplification does; with `--follow` it lists no merges. `--follow` gave the same commits as `git log --follow` for all 40 renamed files tried.
- `scn blame` gives lines a merge brought in to the commit on the branch they came from, not to the merge; 99.2% of lines agree with `git blame` on 40 files.
- Paths given to `log`, `show`, `diff` and `blame` are relative to the current directory; `blame REV:PATH` still starts at the root.
- `--oneline`, `reflog` and `watch` print git's subject: the first paragraph of the message, lines joined.

**Server**
- **Repacking on its own.** Every 15 minutes the server adds up what was written since the last repack, and repacks when that is 256 MiB or more (as after a large import), or when a day has passed and anything was written. One node repacks at a time. `--repack-after`, `--repack-every` and `--repack-check-interval` set it; `--repack-after 0 --repack-every 0s` turns it off. `scion admin repack` still works and counts as a repack.
- **Deployment:** `deploy/prd` is a production compose file (authentication required, secrets from `.env`), next to `deploy/dev` for trying things out; it replaces `deploy/compose`.

## Compatibility

- The metadata store gets two migrations, run at startup: `tag_annotations` and the ref log's `actor` column. Moves recorded before this release name no one in `scn reflog`.
- Blame results cached by earlier servers are computed again the first time each file is asked for, since lines from merges are attributed differently.
- `scn grep` without a revision now includes local changes; give `HEAD` to search the commit alone.
- Automatic repacking is on by default. It rewrites everything reachable each time, so on a large installation set the thresholds, or turn it off and keep running `scion admin repack` yourself.
- `scn reflog` needs a v0.1.12 server, and so do annotated tags and `scn log --follow`.
