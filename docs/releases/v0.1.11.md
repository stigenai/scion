Plain `git` can now clone, fetch and push Scion repositories: the server speaks git's smart HTTP protocol at the same address and URL as `scn`. There is nothing to migrate, and the gateway is on by default; `scion server --no-git` turns it off.

## Install

```sh
# The client, scn
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh
# and the server, as a service on 127.0.0.1:7080 (systemd on Linux, launchd on macOS)
curl -fsSL https://raw.githubusercontent.com/OpenCSGs/scion/main/install.sh | sh -s -- --server
```

**Release packages.** As in v0.1.10, the server `scion` comes in `scion-server-v0.1.11-<target>.tar.gz` and the client in `scn-v0.1.11-<target>.tar.gz`, with `SHA256SUMS` and `install.sh`. The targets are:
- `x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu` (glibc 2.35 or newer);
- `aarch64-apple-darwin` and `x86_64-apple-darwin`.

**Docker image.** `opencsghq/scion:0.1.11` on Docker Hub, also as `opencsg-registry.cn-beijing.cr.aliyuncs.com/opencsghq/scion:0.1.11`, for `linux/amd64` and `linux/arm64`; both are also tagged `latest`.

## Changes

See [using git with Scion repositories](https://github.com/OpenCSGs/scion/blob/main/docs/guide/git-clients.md) for the details and what is not available yet.

- **`git clone`, `fetch` and `pull`.** A repository's git URL is its `scn` URL (`git clone http://HOST:7080/REPO`), with protocol v2 and v0. Branches are `refs/heads/*`, tags `refs/tags/*`, and `HEAD` is the default branch. Commits imported from git keep their original SHAs; commits made with `scn` get a SHA computed from their content, which `git fsck --strict` accepts.
- **`git push`.** New commits land with the SHAs they were pushed with, signed commits included. Branches and lightweight tags can be created, moved and deleted. A push that is not a fast-forward is refused (`fetch first`); `git push --force` needs the same `land` permission as `scn`. Pre-land checks and ref events apply to pushes.
- **Shallow and partial clones.** `--depth`, `--shallow-since` and `--unshallow` work, and so do `--filter=blob:none` and `--filter=blob:limit=SIZE`.
- **Smaller packs.** Changed trees and files are sent as deltas against their previous version, and pushes are spooled to a temporary file instead of memory (up to 16 GiB).
- **Credentials.** The same tokens as `scn`, as the password of HTTP Basic authentication with any user name, or as `Authorization: Bearer`.
- **`scn import git` keeps the raw git commit** when Scion's fields cannot rebuild it exactly (such as signed commits), in the `git.commit` extension, so the gateway can serve it with its original SHA.

## Compatibility

Signed commits imported with an earlier `scn` have no raw git object, and neither can commits with submodules be served yet. Fetching them fails with a plain git error that says so; import the git repository again into a new Scion repository with `scn` 0.1.11, or keep using `scn clone`. SSH URLs, annotated tags and `git push --atomic` are not supported yet.
